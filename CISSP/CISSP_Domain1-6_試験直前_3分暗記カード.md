# CISSP Domain 1〜6｜試験直前・3分暗記カード

> [詳しい解説：分類別・最重要チートシート](./CISSP_Domain1-6_分類別_最重要チートシート.md)  
> 目的：答案を選ぶための**比較**を、短時間で繰り返し想起する。

## ① CISSPの答え方（最初の30秒）

**事業目標 → 資産と保護要件 → リスク評価 → 統制選択 → 承認 → 運用 → 証拠評価 → 改善**。  
**経営＝リスク受容**、**オーナー＝要件・権限決定**、**カストディアン＝実装運用**、**監査＝独立性・客観性を持つ検証**。  
**人命・安全性を最優先**。導入済み≠有効。委託≠責任放棄。ログイン済み≠全操作許可。

## ② モデル・原則（逆転するものをセットで）

| 見た瞬間に思い出す条件 | 反射的に答える |
|---|---|
| **機密性／高位を読めない・低位に書けない** | **BLP：No Read Up・No Write Down** |
| **完全性／低位を読めない・高位に書けない** | **Biba：No Read Down・No Write Up** |
| **競合A社の秘密を見たら競合B社は不可** | **Brewer–Nash / Chinese Wall** |
| **商取引の正規手順・二人承認** | **Clark–Wilson：CDI/UDI/TP/IVP** |
| **主体・オブジェクトの権限生成・削除** | **Graham–Denning** |
| **権限が漏れる可能性を解析** | **HRU** |
| **一人の権限を最小化** | Least Privilege |
| **一人で申請・承認を完結させない** | Separation of Duties |
| **障害時も安全を維持** | Fail Secure |
| **最初から安全に設定** | Secure by Default |

## ③ 法律・規格・保証（最重要）

| 領域 | 連想 |
|---|---|
| EU個人情報 | **GDPR**（目的限定・最小化・削除・説明責任） |
| 米国医療PHI | **HIPAA** |
| 米国金融機関の顧客情報 | **GLBA** |
| 米国上場企業の財務報告 | **SOX** |
| 米国教育記録／13歳未満のオンライン個人情報 | **FERPA／COPPA** |
| カード会員データの業界基準 | **PCI DSS**（法律ではない） |
| ISMS要求事項／管理策ガイド／リスク管理 | **ISO 27001／27002／27005** |
| BCMS要求事項／システムの継続計画 | **ISO 22301／NIST SP 800-34** |
| NISTの管理策／評価方法／RMF | **800-53／800-53A／800-37** |
| CSF 2.0の6機能 | **Govern–Identify–Protect–Detect–Respond–Recover** |
| 財務報告統制／TSC／一般公開向け | **SOC 1／SOC 2／SOC 3** |
| 時点の設計／期間の運用有効性 | **Type 1／Type 2** |

## ④ 数字・公式

- **SLE = AV × EF**、**ALE = SLE × ARO**。資産1000万円、被害40%、2年に1回 → **ALE 200万円／年**。
- **RPO＝過去にどこまで戻るか**、**RTO＝何時間で復旧か**、**WRT＝復旧後の業務再開作業**、**MTD/MAD＝耐えられる最大停止**。
- **Tier I＝基本、II＝冗長容量、III＝同時保守可能、IV＝耐障害**。
- **AES＝128ビットブロック、128/192/256ビット鍵**。
- **FAR＝他人を通す、FRR＝本人を拒む**。厳しくすると通常FAR↓・FRR↑。

## ⑤ 技術の取り違えを封じる

| 質問 | 答え |
|---|---|
| ディレクトリ検索／チケット認証 | **LDAP／Kerberos** |
| ネットワークAAA／機器管理AAA | **RADIUS／TACACS+** |
| API認可の委任／ログイン認証 | **OAuth 2.0／OIDC** |
| XMLアサーションのSSO | **SAML 2.0** |
| 一度のログイン／他組織との信頼関係 | **SSO／FIM** |
| 身元証明／認証強度／連携強度 | **IAL／AAL／FAL** |
| ポリシー判断／執行 | **PDP／PEP** |
| 所有者裁量／強制ラベル／役職／属性 | **DAC／MAC／RBAC／ABAC** |
| 必要な時間だけ／必要な権限だけ | **JIT／JEA** |
| 鍵合意／大量データ暗号／送信者の証明 | **(EC)DH／AES／署名** |
| 暗号化しないIPsec／暗号化可能なIPsec | **AH／ESP** |
| VLAN（L2）／VRF（L3） | **802.1Q／ルーティングテーブル分離** |
| Wi-Fiの規格／接続ポート認証 | **802.11／802.1X** |
| ログの相関分析／実ユーザー性能計測 | **SIEM／RUM** |

## ⑥ ポートの最小セット

**SSH 22、DNS 53、HTTP 80、Kerberos 88、HTTPS 443、SMB 445、RDP 3389、LDAP 389、LDAPS 636、RADIUS UDP 1812/1813、TACACS+ TCP 49、IKE UDP 500、NAT-T UDP 4500、L2TP UDP 1701、BGP TCP 179。**  
**ESPはIPプロトコル番号50、AHは51**（ポートではない）。

## ⑦ 監査・テストの場面から答える

| 問題文 | 答え |
|---|---|
| 規程・ログ・設定を確認 | Examine |
| 現場担当者に手順を聞く | Interview |
| 実際の動作を確かめる | Test |
| コードを実行せずに解析 | SAST |
| 無効入力を与える | Negative Testing |
| 悪用ケースを想定 | Misuse Case |
| 定期的に仮想顧客が購入操作 | Synthetic Monitoring |
| 実顧客の遅延を観測 | RUM |
| 弱点の是正・担当者・期限を管理 | POA&M |
| テスト前に許可範囲と禁止事項を合意 | ROE |

## ⑧ 試験終了まで維持したい一文

**「何を守るのか、誰に責任があるのか、何がリスクなのか、どんな管理策が適切か、証拠で効いていると確認できるか」**。  
これを順番に考えれば、単なる技術名の暗記に引きずられにくい。
